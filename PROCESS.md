# Process overview

## What I built

An interactive circle-of-fifths explainer you **see and hear at the same time**. Click a wedge and its triad sounds, the wheel outlines the three slices its chords live in, roman numerals appear on those six wedges, the piano lights the notes, and a line of text names them for a reader who cannot hear. Colour is the second channel: Mr Mars' cited scheme, fixed against the theme because it is content, and never the only signal — every wedge is lettered. Neither channel teaches the idea alone, which is the page's whole point. Three more things are part of the explanation, not extras: it reads in five languages, every wedge label is measured against WCAG AA contrast, and it follows the reader's light or dark setting.

## The moments that mattered

**A test that passed without running.** I wrote a test that clicked a wedge and checked the numerals appeared. It passed — because JSDOM never runs `<script type="module">`, so it had checked an untouched page. The obvious move was to make it work, with `runScripts` or a browser runner. I deleted it instead and moved the line: logic now lives in a plain module with no DOM, tested against values I checked by hand (C major's triad at 261.63 / 329.63 / 392.00 Hz), the spec checks only the structure the script needs, and the rendering I check in a browser. Then I wrote the rule into `CLAUDE.md`, so the next session inherits it ([`806b816`](https://github.com/comp4020-agentic-coding-studio/comp4020-ass1-PetreWei/commit/806b816), on [`525b1ef`](https://github.com/comp4020-agentic-coding-studio/comp4020-ass1-PetreWei/commit/525b1ef)).

**The highlight was lying about the sound.** In some keys Happy Birthday lit keys that were not sounding, and its last line played an octave too low. Two bugs, one hiding the other: the melody was pinned to the tonic rather than a fifth below it, pushing 12 of the 24 keys off the keyboard, and `findPianoKey` hid that by falling back to the nearest octave of the same note. The obvious fix was a longer keyboard. Instead I re-pinned the melody to its own lowest note, then deleted the fallback: a wrong highlight looks exactly like a right one, so lighting nothing is honest. I checked it with a MutationObserver recording each key as it lit, across all 24 keys, not by eye ([`640421f`](https://github.com/comp4020-agentic-coding-studio/comp4020-ass1-PetreWei/commit/640421f)).

**A red check that was not about my site.** Splitting the theory page took the site from 2 Wikipedia links to 10, and CI's link check went red: Wikipedia rate-limits a shared CI machine, and it only ever failed there. The obvious fix was one line in the workflow to skip that host. I drafted it and threw it away: the course CI is the sensor I have to satisfy, and editing it turns a real signal into a green light. I cut the citations back and capped the count in my own tests; when a second site began blocking CI I stopped patching and removed the dependency. Citations keep their full URL as selectable text, but nothing is a link — the rule got stricter, not looser: nothing external, anywhere ([`4bd923d..90fdf9d`](https://github.com/comp4020-agentic-coding-studio/comp4020-ass1-PetreWei/compare/4bd923d...90fdf9d)).

**Measuring reversed a decision I had made on purpose.** Asked for accessibility, I measured before changing anything. Every wedge label used the same white ink, chosen so a future dark theme would have one value to swap. E major came back at 1.57:1, and 9 of the 24 labels fell below WCAG AA's 4.5:1. The obvious fix was to darken those colours, but the sameness *was* the cause, so I reversed my own decision: each wedge now picks white or near-black by measured contrast, worst case 4.61:1. The same audit found `:focus-visible` identical to `:hover`, so the wheel showed nothing to a keyboard user. 24 contrast checks now run in CI, anchored on the WCAG formula itself — black on white must be exactly 21:1 — so they cannot pass on a broken formula ([`c8ade29`](https://github.com/comp4020-agentic-coding-studio/comp4020-ass1-PetreWei/commit/c8ade29)).
